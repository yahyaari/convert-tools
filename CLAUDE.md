## Architecture

Astro 5 static site (`output: "static"`) for **SAKU Studios** — a brand / portfolio / products-and-solutions landing site hosted at `https://www.sakustudios.com.tr`. First product shipped on the site: **QR Menü** (a QR menu product for restaurants/cafés built on Supabase, presented here as a marketing/detail page; the product itself lives in a separate project). More products will be added over time.

### Pages
- `src/pages/index.astro` — landing (hero → products grid → about placeholder → contact).
- `src/pages/qr-menu.astro` — product detail page (hero → features grid → preview placeholder → tech chips → contact).

Both pages share three components and follow the same script pattern at the bottom (initialize lang + wire `.lang-btn` click handlers).

### Shared building blocks
- `src/layouts/BaseLayout.astro` — HTML shell; centralizes SEO (canonical, hreflang `tr`/`en`/`x-default`, OG/Twitter) and builds one JSON-LD `@graph` per page by merging WebSite + Organization + whatever the page passes in `jsonLd` prop (page entries get `@context` stripped).
- `src/components/Header.astro` — sticky header with wordmark, anchor nav, TR/EN `.lang-btn` switch.
- `src/components/Footer.astro` — brand + contact links + copyright.
- `src/components/ContactSection.astro` — WhatsApp + mail cards + contact form. Form submits to Web3Forms via `fetch` (see "Contact form" below).
- `src/consts.ts` — `SITE` (name, descriptions, url, default OG image, logos) **and** `SITE.contact` (`whatsapp`, `whatsappDisplay`, `email`, `web3formsKey`). Update here, not in pages.
- `src/styles/global.css` — theme variables (slate + blue accent, light mode only), buttons, dark hero, section/card/form primitives. Pages extend this with page-scoped `<style>` only when truly needed.

### i18n — client-side swap, shared URL
- `src/lib/i18n.ts` — TR/EN dictionaries keyed by flat string keys (e.g. `hero_title`, `qr_feat1_desc`). Each key maps to an element with `id="t-<key>"`.
- `src/utils/lang.ts` — `detectLang()` reads `localStorage.lang` → navigator/timezone fallback; `applyLang(lang, dict)` sets `document.documentElement.lang`, walks every `#t-*` node, and toggles `.lang-btn.is-active`.
- Both languages share the same URL; hreflang alternates in `BaseLayout` all point to the same canonical. Do **not** move to URL-segmented i18n (`/tr/`, `/en/`) without also rewriting hreflang logic.
- When adding content: add a key to **both** `tr` and `en` in `i18n.ts`, then use `<span id="t-<key>">TR default text</span>` in markup. The TR default is what SSR renders; EN only appears after the hydration script runs (brief FOUC accepted).

### Contact form
`ContactSection.astro` posts to `https://api.web3forms.com/submit` with `access_key` read from `SITE.contact.web3formsKey` in `consts.ts`. **The key is intentionally empty** — it must be filled in by getting a free key from https://web3forms.com (verified against `sakustudioss@gmail.com`) and pasting it into `consts.ts`. If the key is empty, `data-enabled="0"` makes the form render but any submit attempt shows the `contact_form_disabled` message instead of calling the API. WhatsApp and mail links work regardless.

### Deployment
Static output, Cloudflare Pages compatible (25 MiB per-file limit — no heavy wasm/binaries should be added). Sitemap is auto-generated by `@astrojs/sitemap`; do not hand-maintain `public/sitemap.xml`. `public/robots.txt` blocks `GPTBot`, `CCBot`, `Google-Extended`.
